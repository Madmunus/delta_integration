# Дельта — система управления клиентской базой бухгалтерской фирмы

Прототип веб-системы для агрегации данных о клиентах из «1С» (OData),
управления задачами, контроля сроков отчётности и договоров.

## Возможности

- **ФТ-1** Сводный реестр клиентов: синхронизация из учётных баз «1С» через OData
  + ручные атрибуты (статус, ответственный, заметки).
- **ФТ-2** Отображение входящих документов из «1С:Документооборот» в карточке клиента.
- **ФТ-3** Задачи с привязкой к клиентам/сотрудникам, сроками и приоритетами;
  автогенерация задач по справочнику сроков (APScheduler).
- **ФТ-4** Справочник видов отчётности (периодичность, срок сдачи) и визуальный
  контроль ближайших/просроченных сроков в разрезе клиентов.
- **ФТ-5** Договоры на сопровождение: перечень услуг, стоимость, сроки действия.
- **ФТ-6** Сводные отчёты для руководителя: клиенты, задачи, договоры, сроки.
- **ФТ-7** Ролевая модель: руководитель (полный доступ) / сотрудник (только свои клиенты и задачи).

## Технологии

Python 3.10+, Flask, SQLAlchemy, Flask-Login, Flask-WTF (CSRF), Jinja2,
Bootstrap 5 (хранится локально в `static/vendor/`), requests, APScheduler.
СУБД: SQLite (разработка) / PostgreSQL (продакшен).

## Быстрый старт (разработка)

```bash
cd delta_integration
python -m pip install -r requirements.txt
python seed.py                    # демо-данные
python app.py                     # http://127.0.0.1:5000
```

## Продакшен (PostgreSQL)

```bash
set DELTA_ENV=production
set DELTA_SECRET_KEY=<случайная строка>
set DELTA_DATABASE_URL=postgresql+psycopg2://user:pass@host:5432/delta
python -m pip install psycopg2-binary gunicorn
gunicorn -w 4 -b 0.0.0.0:8000 "app:app"
```

> Планировщик (APScheduler) в WSGI-окружении лучше вынести в отдельный процесс
> или cron: `python -m services.run_jobs`.

### Реестр клиентов

- **Поиск по таблице** — по наименованию, ИНН, КПП и заметкам.
- **Фильтры** — по статусу и диапазону дат добавления («с» / «по»).
  Поля дат — стандартные поля выбора даты с календарём; в запрос
  передаётся формат `гггг-мм-дд`, при этом параметры URL также принимают
  `дд.мм.гггг`. Руководителю доступен ещё и фильтр по ответственному,
  включая вариант «не назначен».
- **Быстрая очистка** — кнопка «×» всегда видна у поля поиска и у каждой
  даты; она очищает только это поле на клиенте, без отправки запроса
  на сервер, и сохраняет остальные фильтры и сортировку.
  Кнопка **«Сброс»** после «Найти» очищает все фильтры сразу.
- **Сортировка** — клик по заголовку столбца (Наименование, ИНН, КПП,
  Статус, Ответственный, Добавлен) переключает три состояния:
  по возрастанию ▲ → по убыванию ▼ → сортировка отключена (по умолчанию).
  По умолчанию сначала идут активные клиенты, затем архивные, внутри
  группы — по наименованию. Состояние сортировки сохраняется при
  фильтрации и переключении страниц.
- **Действия** — «Редактировать» открывает карточку клиента; «Удалить»
  (только руководитель) удаляет клиента вместе со всеми связанными
  договорами, задачами и документами (каскадное удаление).

## Интеграция с 1С (OData)

1. В учётной базе включите публикацию стандартного OData-интерфейса
   (Администрирование → Публикация на веб-сервере → «Стандартный интерфейс OData»).
2. Создайте пользователя 1С с правами на чтение нужных справочников.
3. В системе: «Базы 1С» → «Добавить базу», укажите
   `http://server/base/odata/standard.odata/`, логин и пароль.
4. Синхронизация клиентов выполняется автоматически (по умолчанию раз в час)
   или вручную кнопкой «Синхронизировать сейчас».

Сопоставление клиентов: по `Ref_Key` (GUID объекта 1С), затем по ИНН.
Ручные атрибуты при синхронизации не перезаписываются.

## Тестирование системы

Страница **«Тестирование»** (меню руководителя, после «Пользователи»)
выполняет шесть сценариев проверки функциональных требований:

| Сценарий | ФТ | Проверка |
|---|---|---|
| 1 | ФТ-1 | синхронизация справочника клиентов из тестовой базы «1С»; отсутствие дублей при повторном запуске |
| 2 | ФТ-2 | запрос документов клиента из «1С:Документооборот» через OData; отображение в карточке клиента |
| 3 | ФТ-3 | создание задачи с привязкой к клиенту и исполнителю; смена статусов; виджет «Мои задачи» |
| 4 | ФТ-4 | формирование задач по справочнику сроков; корректность сроков; архивы не обрабатываются |
| 5 | ФТ-6 | отчёты по клиентской базе и задачам; корректность агрегированных показателей |
| 6 | ФТ-7 | вход под сотрудником; видимость только закреплённых клиентов |

Каждый сценарий выполняется в изолированном приложении с собственной
базой SQLite в памяти: рабочие данные не затрагиваются, обращения к «1С»
имитируются подставными ответами OData. Тот же набор сценариев доступен
из командной строки:

```bash
python -m tests.runner
```

Команда возвращает код выхода 0 (все пройдены) или 1 (есть непройденные).

## Безопасность

- Пароли хранятся в виде хешей (`generate_password_hash`, Werkzeug/PBKDF2).
- Политика паролей: не менее 13 символов, минимум одна цифра,
  заглавная и строчная латинские буквы, спецсимвол.
- Все формы защищены CSRF-токенами (Flask-WTF).
- SQLAlchemy ORM исключает SQL-инъекции; Jinja2 автоматически экранирует вывод.
- Проверка прав в каждом обработчике: сотрудник видит только «своих» клиентов и задачи.
- Удаление клиентов и доступ к отчётам/тестированию/пользователям — только для руководителя.
- HTTP-запросы к 1С выполняются с таймаутами и обработкой ошибок.
