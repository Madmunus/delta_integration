# Дельта — система управления клиентской базой бухгалтерской фирмы

Прототип веб-системы для агрегации данных о клиентах из «1С» (OData),
управления задачами, контроля сроков отчётности и договоров.

## Возможности

- **ФТ-1** Сводный реестр клиентов: синхронизация из учётных баз «1С» через OData
  + ручные атрибуты (статус, ответственный, заметки).
- **ФТ-2** Отображение входящих документов из «1С:Документооборот» в карточке клиента.
- **ФТ-3** Задачи с привязкой к клиентам/сотрудникам, сроками и приоритетами;
  автогенерация задач по справочнику сроков (APScheduler).
- **ФТ-4** Справочник видов отчётности (периодичность, срок сдачи) и визуальный
  контроль ближайших/просроченных сроков в разрезе клиентов.
- **ФТ-5** Договоры на сопровождение: перечень услуг, стоимость, сроки действия.
- **ФТ-6** Сводные отчёты для руководителя: клиенты, задачи, договоры, сроки.
- **ФТ-7** Ролевая модель: руководитель (полный доступ) / сотрудник (только свои клиенты и задачи).

## Технологии

Python 3.10+, Flask, SQLAlchemy, Flask-Login, Flask-WTF (CSRF), Jinja2,
Bootstrap 5 (хранится локально в `static/vendor/`), requests, APScheduler.
СУБД: SQLite (разработка) / PostgreSQL (продакшен).

## Быстрый старт (разработка)

```bash
cd delta_integration
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt
python seed.py                    # демо-данные
python app.py                     # http://127.0.0.1:5000
```

Демо-учётные записи:

| Роль | Email | Пароль |
|---|---|---|
| Руководитель | `admin@delta.local` | `admin123` |
| Сотрудник | `ivanov@delta.local` | `ivan123` |
| Сотрудник | `petrova@delta.local` | `anna123` |

## Продакшен (PostgreSQL)

```bash
set DELTA_ENV=production
set DELTA_SECRET_KEY=<случайная строка>
set DELTA_DATABASE_URL=postgresql+psycopg2://user:pass@host:5432/delta
pip install psycopg2-binary gunicorn
gunicorn -w 4 -b 0.0.0.0:8000 "app:app"
```

> Планировщик (APScheduler) в WSGI-окружении лучше вынести в отдельный процесс
> или cron: `python -m services.run_jobs`.

## Интеграция с 1С (OData)

1. В учётной базе включите публикацию стандартного OData-интерфейса
   (Администрирование → Публикация на веб-сервере → «Стандартный интерфейс OData»).
2. Создайте пользователя 1С с правами на чтение нужных справочников.
3. В системе: «Базы 1С» → «Добавить базу», укажите
   `http://server/base/odata/standard.odata/`, логин и пароль.
4. Синхронизация клиентов выполняется автоматически (по умолчанию раз в час)
   или вручную кнопкой «Синхронизировать сейчас».

Сопоставление клиентов: по `Ref_Key` (GUID объекта 1С), затем по ИНН.
Ручные атрибуты при синхронизации не перезаписываются.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DELTA_SECRET_KEY` | ключ сессий (обязателен в проде) | dev |
| `DELTA_DATABASE_URL` | строка подключения | SQLite `delta.db` |
| `DELTA_SYNC_INTERVAL` | период синхронизации, сек | `3600` |
| `DEADLINE_LEAD_DAYS` (DELTA_DEADLINE_LEAD_DAYS) | за сколько дней до срока создавать задачи | `7` |

```
│   └── reports.py       # dashboard и отчёты
├── templates/           # Jinja2
└── static/css/          # стили
```

## Безопасность

- Пароли хранятся в виде хешей (`generate_password_hash`, Werkzeug/PBKDF2).
- Все формы защищены CSRF-токенами (Flask-WTF).
- SQLAlchemy ORM исключает SQL-инъекции; Jinja2 автоматически экранирует вывод.
- Проверка прав в каждом обработчике: сотрудник видит только «своих» клиентов и задачи.
- HTTP-запросы к 1С выполняются с таймаутами и обработкой ошибок.
